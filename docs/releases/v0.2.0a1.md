# Harness Factory 0.2.0a1

This is the first public alpha of Harness Factory: a working, non-normative
implementation of HDP Draft 0.1 with one complete Codex software-development
adapter and an evidence-aware existing-harness analyser.

## Install

```bash
uv tool install \
  https://github.com/jremick/harness-factory/releases/download/v0.2.0a1/harness_factory-0.2.0a1-py3-none-any.whl
harness doctor
```

## Included

- the seven-command `harness` workflow: `init`, `build`, `install`, `audit`,
  `verify`, `release`, and `doctor`;
- a conservative `codex-sdlc` project template and target-neutral HDP/HIR
  pipeline;
- deterministic Codex rendering for `AGENTS.md`, Agent Skills, project settings,
  policy/evidence helpers, source maps, HarnessCard, and manifests;
- fail-closed, manifest-owned installation with dry-run, digest, symlink,
  ownership, local-modification, and stale-file checks;
- exact generated-harness round-trip analysis plus evidence-qualified partial
  reconstruction for foreign harnesses;
- content-addressed verification evidence, unsigned digest-only attestations,
  and post-package tamper detection; and
- the advanced `hdp` interface for contract and compiler development.

## Compatibility

The canonical schema is HDP Draft `0.1.0`,
`urn:hdp:schema:0.1.0`, SHA-256
`4cb4a85dcdfe6b176be5760a1f109c720a66ea80a6179f94928e3683f1566e96`.
The only complete adapter is Codex, and it compiles the target-neutral
`software-development` profile through a separate target binding.

The distribution changed from the internal prototype name `hdp-reference` to
`harness-factory`. The lower-level `hdp` executable remains for the v0.1 command
surface, but Python import compatibility is not promised during alpha.

## Verification and limits

See the source-snapshot and CI-backed [verification report](../verification-report.md) for the
final commands, live task outcomes, failures, and release-asset installation
read-back. This release is intended for controlled experiments, not unattended
production use.

This tag releases the factory software, not a release-eligible generated
harness. The four managed Codex tasks passed, but the current Codex
`workspace-write` probe could read a canary outside its workspace. The
workspace-only read gate therefore remains failed and `harness release` remains
fail-closed for this evidence set. See
[ADR 0014](../decisions/0014-separate-factory-alpha-from-harness-release-eligibility.md).

- Generated command helpers are recorders and prechecks, not an OS sandbox.
- A valid HDP or passing generated tests do not prove outcome fitness, security,
  or operational assurance.
- Attestations are unsigned and prove detectable integrity, not builder identity.
- Model aliases may not expose an immutable provider-side model revision.
- Alpha contracts and commands may change before beta.
- Foreign-harness reconstruction is experimental and has not passed the
  held-out zero-false-assertion promotion gate described in ADR 0015.
